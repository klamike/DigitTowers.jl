DigitTowers.jl

DigitTowers searches for decimal numbers that reproduce themselves when their digits form a power tower and an outer root is taken. The default problem uses single digits in their original order, a square root, and a right-associated tower:

\[\sqrt{2^{\,6^{\,2^{\,1^{\,4^4}}}}}=262144.\]

The default search uses exact number theory: decimal prefix bounds locate the only possible power for each base, then capped arithmetic checks its suffix. The original JuMP constraint programming model remains available as method=:cp. It uses finite transition tables reformulated as a mixed-integer model for HiGHS. Every backend uses exact candidate arithmetic and checks each returned answer again with integer arithmetic.

Run a search

From the package directory, instantiate the environment:

julia --project=. -e 'using Pkg; Pkg.instantiate()'

Then start Julia with julia --project=.:

julia> config = Config();

julia> result = search(config);

julia> length(result.solutions)
1

julia> string(only(result.solutions).number)
"262144"

julia> result.complete
true

julia> result.method
:prefix

julia> verify(only(result.solutions), config)
true

complete=true means the backend exhausted the configured finite search. It applies to this digit length and grammar. A solution limit, or a time limit in the CP backend, leaves it false.

Select a method

methodAlgorithm
:prefixDefault: exact leading-prefix windows, followed by capped suffix evaluation
:directEnumerate primitive powers, then evaluate the candidates directly
:cpOriginal JuMP/HiGHS candidate and transition constraints
:nemoPrefix search using Nemo/FLINT integer logarithms and powers
search(Config(); method=:cp)
search(Config(); method=:direct)

The optional Nemo backend is activated by loading Nemo in an environment where it is installed:

using DigitTowers, Nemo
search(Config(); method=:nemo)

Nemo is a weak dependency; the default search does not load it. See Performance for algorithm comparisons and measured timings.

For a range of lengths and root orders, sweep searches the single-digit grammar in one pass and derives the only possible root from each candidate's suffix:

sweep(2:100; roots=collect(1:9))

Change the rules

Root orders, digit restrictions, grouped blocks, and additions inside the outer exponent are configurable. For example, grouping the suffix as 56 gives:

julia> config = Config(ndigits=3, roots=[7], block_widths=[1, 2]);

julia> result = search(config);

julia> println(expression(only(result.solutions), config))
root_7((2^56)) = 256

julia> result.complete
true

Read Formulation for the prefix algorithm, constraints, and completeness proof, Configuration for the expression grammar, Results for the bounded searches, and API for the Julia interface.

Beyond the original puzzle
