API

search is the usual entry point, taking a Config and method=:prefix by default. :direct, :cp, and optional :nemo select the other search backends. Their results share solutions, complete, status, candidates, cap, and method; see Configuration for status semantics and Performance for backend selection.

sweep searches a range of lengths and root orders in the single-digit grammar with one primitive-power pass. It derives the root from the suffix instead of evaluating that suffix separately for each allowed root. Its result uses method=:sweep; its docstring explains the candidate-count and cap fields, which differ from those of a fixed-configuration search.

build_model always constructs the original CP formulation. It exposes the JuMP model, configuration, candidate list, grammar, selector variables, and cap for inspection or additional constraints. Its empty-candidate result has no digit, root, exponent, block, or suffix variables.

Candidate stores the exact answer as number::BigInt, its root order, the effective outer exponent, decimal digits, and parsed BigInt blocks. Keep the configuration with each answer: it supplies the root-prefix width, block widths, operators, and zero convention needed by verify and expression.

Explorations

root_spectrum removes the root-order bound entirely. Its RootCertificate stores an exact small root or a symbolic large-root witness; use verify_root_certificate (or verify) to check it independently.

synthesize finds minimum-cost expressions in a finite grammar and returns SynthesisCertificate witnesses accepted by verify and expression. synthesize_frontier retains every nondominated join/addition cost pair. anagram_towers permits reordering single digits and minimizes changed positions, returning AnagramCertificate witnesses for the original target integer. radix_sweep searches other numeral systems and returns RadixSolution objects with explicit integer-valued digits.

tower_mod evaluates towers modulo an integer; modular_fixedpoints and modular_dynamics exhaust finite congruence puzzles and functional graphs. tower_isdefined recognizes the forbidden-00 language, while tower_language_counts counts it by matrix exponentiation. modular_nearpoints exhausts minimum-distance variants with an exact residue bound. modular_orbit follows one starting word using Brent's algorithm, without enumerating the whole domain.

Public docstrings

DigitTowers.AnagramCertificate — Type
AnagramCertificate

A digit-reordering witness for anagram_towers. number keeps its ordinary decimal value; digits records a permutation used as the tower. root is external and exponent is the suffix value. moves counts positions whose digit differs from the original numeral, rather than transpositions. The chosen zero_to_zero convention belongs to the certificate.

DigitTowers.Candidate — Type
Candidate

A necessary-condition assignment (or a verified solution): number::BigInt, root, exponent, decimal digits, and parsed blocks. A precomputed candidate becomes a solution only after its suffix evaluates to exponent. Use verify to check the complete expression.

DigitTowers.Config — Type

A fixed expression grammar. By default: sqrt(d1^(d2^(...^dL))). root_digits consumes that many leading digits of N as the root order. block_widths partitions the remaining digits, including the outer base. operators joins blocks RIGHT-ASSOCIATIVELY; the first must be :^. The supported operators are :^ and :+ (addition is inside the outer power).

DigitTowers.RadixSolution — Type
RadixSolution

An exact single-digit tower solution in an arbitrary positional radix. number::BigInt is the value in ordinary integer notation; digits are most-significant first, with every digit represented by its integer value. root is an external root order and exponent is the suffix tower value. The defining identity is digits[1]^exponent == number^root.

DigitTowers.RootCertificate — Type
RootCertificate

An exact certificate that a digit numeral admits a positive integer external root order, with no upper bound on that order. number = primitive^h and its leading digit is primitive^g. The suffix is c^T, where c=digits[2]; k=h/gcd(h,g) must divide c^T. required_tail_threshold certifies the necessary and sufficient lower bound on T from prime valuations of k.

root is an exact BigInt when it is at most root_display_limit; otherwise it is nothing, certifying that the unique root is larger than that limit. Use expression for its symbolic value. The stored zero_to_zero convention is part of the certificate, and digits are most-significant first.

DigitTowers.SynthesisCertificate — Type
SynthesisCertificate

A certified expression returned by synthesize or synthesize_frontier. candidate and config are ordinary DigitTowers objects, so the result can also be checked or searched with the existing backends. For scalar synthesis, cost is the configured weighted sum of concatenations and additions. For a Pareto frontier it is their unweighted sum; both coordinates determine membership. Each deleted digit boundary counts as one concatenation.

DigitTowers.anagram_towers — Method
anagram_towers(number; roots=[2], zero_to_zero=:forbid,
               max_states=1_000_000, max_exponent=1_000_000)

Reorder the decimal digits of a fixed integer number >= 10 into a pure, right-associated power tower whose external root gives that original number. Each digit is used exactly once, with no concatenation. A leading base must be at least two. Return one AnagramCertificate for each feasible (root, leading base), minimizing the number of changed digit positions; lexicographic order breaks ties reproducibly. This counts changed positions, not the number of swaps.

The exact dynamic program merges equal (remaining digit counts, capped suffix value) states. Repeated digits never create duplicate branches, and all root orders for one leading base share a chart. The arithmetic identity number = a^h, base = a^g forces the target suffix to be root*h/g. Saturation above the largest target preserves zero, one, and undefined 0^0, including undefined expressions hidden beneath a one.

Return (; certificates, complete=true, targets, states, method=:anagrams). states counts stored semantic chart states across leading bases; targets counts arithmetically possible (root, base) pairs. Exceeding either resource limit throws an error, so a returned result is complete for the finite digit multiset and supplied root orders. The algorithm avoids enumerating all permutations but its count-vector lattice can still grow exponentially.

Examples

result = anagram_towers(262144)
@assert all(verify, result.certificates)
@assert minimum(x.moves for x in result.certificates) == 0
DigitTowers.build_model — Function

Build a bounded CP model expressed in JuMP. HiGHS solves JuMP's MIP reformulations of the MOI.Table constraints. The first table is written explicitly with one-hot selectors so solutions can be enumerated cheaply.

DigitTowers.expression — Method
expression(x::Candidate, config::Config)

Format an assignment with explicit right-associative parentheses and root order. Configured block widths, including leading zeros, are preserved.

DigitTowers.expression — Method
expression(certificate::RootCertificate)

Display a root-spectrum solution, using tower([d1,d2,...]) for a right-associated tower with integer-valued digits. Large root orders stay symbolic and carry the certified strict bound r > root_display_limit.

DigitTowers.expression_radix — Method
expression_radix(solution)

Format a RadixSolution with explicit right association, integer-valued digit labels, and its bracketed radix numeral. For example, [2,10]_11 means 2*11+10, while 2^10 uses the integer exponent ten.

DigitTowers.modular_dynamics — Method
modular_dynamics(ndigits; radix=10, zero_to_zero=:forbid, max_states=100_000)

Exhaust the finite map N -> tower(padded_digits(N)) mod radix^ndigits on all fixed-width words, including leading zeros. Return its directed cycles, each rotated to put its smallest state first; the corresponding basin_sizes count all starting states eventually reaching that cycle. undefined_basin counts states eventually hitting a nested undefined 0^0; undefined counts states whose very next evaluation is undefined. No edges are inferred or sampled.

DigitTowers.modular_fixedpoints — Method
modular_fixedpoints(ndigits; radix=10, allowed_digits=0:radix-1,
                    padded=false, zero_to_zero=:forbid, max_states=100_000)

Find every ndigits-digit number N whose digit tower is congruent to N modulo radix^ndigits. This is a root-free congruence puzzle, distinct from search. With padded=true, enumerate all fixed-width words including leading zeros. complete=true certifies exhaustion of the explicitly bounded domain.

DigitTowers.modular_nearpoints — Method
modular_nearpoints(ndigits; radix=10, metric=:hamming, limit=100,
                   allowed_digits=0:radix-1, padded=false,
                   zero_to_zero=:forbid, max_states=100_000)

Find the closest approaches to a fixed point of the finite map F(N) = tower(padded_digits(N)) mod radix^ndigits. :hamming counts differing digit positions between the two fixed-width words. :circular measures min(abs(F(N)-N), radix^ndigits-abs(F(N)-N)) on the residue circle. The allowed digits restrict inputs; output digits may be arbitrary.

Every eligible input is examined, with undefined towers counted and skipped. minimum_distance and minimum_count are exact even when limit truncates the returned minimizers. Each witness has number, successor, and distance. search_complete=true certifies domain exhaustion; complete additionally certifies that every minimizer is returned. With no defined eligible inputs the minimum is nothing, and the empty result is complete. Leading zeros on input are admitted only by padded=true; comparison always pads the output to the same width. Cached totient chains and a lower bound from the low-order half of the digits prune full-modulus evaluations. full_evaluations and residue_rejections account for every defined input. Distance zero recovers modular fixed points.

DigitTowers.modular_orbit — Method
modular_orbit(start, ndigits; radix=10, zero_to_zero=:forbid,
              max_evaluations=1_000_000, max_width=10_000)

Find the eventual behavior of one orbit of the fixed-width map N -> tower(padded_digits(N)) mod radix^ndigits, using Brent's cycle detection algorithm. Unlike modular_dynamics, this does not enumerate the entire state space. It keeps a constant number of orbit states, in addition to the digits and cached Euler-totient chain used for evaluation. Large moduli have the certification limits of tower_mod.

For termination=:cycle, preperiod is the least number of steps before entering the cycle, period its least positive length, and entry the first cycle state reached from start. For termination=:undefined, undefined_at is the first word whose next evaluation is undefined and distance_to_undefined counts transitions from start to that word. The unused fields are nothing.

evaluations counts all map calls, including the second phase that locates the cycle entry. Exhausting max_evaluations returns complete=false and termination=:limit; all structural fields are then nothing. The width guard throws an error rather than allocating an accidentally enormous modulus. Initial values must lie in 0:radix^ndigits-1; leading zeros are always padding, not omitted tokens.

Return a named tuple with those fields, complete, the domain parameters, and method=:brent. No trajectory or full cycle is retained.

Examples

orbit = modular_orbit(426, 3)
@assert (orbit.preperiod, orbit.period, orbit.entry) == (1, 2, big(456))

# A domain with 2^1000 states, without constructing that functional graph.
wide = modular_orbit(big(2)^999, 1000; radix=2, zero_to_zero=:one)
@assert wide.complete && wide.period == 2
DigitTowers.radix_sweep — Method
radix_sweep(radix, lengths; roots=[2], allowed_digits=0:radix-1,
            distinct_digits=false, zero_to_zero=:forbid, max_solutions=100)

Completely search the single-digit, right-associated tower puzzle in a positional radix radix >= 2, over a nonempty unit range of lengths starting at two. Root orders are external positive integers; roots=[1] searches root-free fixed points. Digits are integers in 0:radix-1, so a radix above ten does not change tower semantics. A leading zero or one cannot yield a nontrivial solution and is excluded.

The exact arithmetic algorithm enumerates primitive powers, not all radix numerals. Write the leading digit b=a^g with primitive a. Unique prime factorization forces N=a^h; after evaluating the digit suffix E, the only possible root is g*E/h. The largest supplied root bounds E, permitting exact capped evaluation even when the actual tower is astronomical. Every reported solution is checked with verify_radix.

Return (; solutions, complete, status, candidates, cap, method=:radix_sweep). candidates counts numeral candidates after digit restrictions but before suffix evaluation. cap is the largest suffix bound used, and cap+1 represents overflow. As in sweep, the entire domain is searched; max_solutions limits returned results, and reaching it conservatively sets complete=false. Memory and runtime grow with the radix and maximum length.

Examples

radix_sweep(10, 2:100; roots=1:9)  # includes the original 262144
radix_sweep(22, 3:100; roots=[1])  # a nondecimal, zero-free fixed point
DigitTowers.root_spectrum — Method
root_spectrum(lengths; radix=10, allowed_digits=0:radix-1,
              distinct_digits=false, zero_to_zero=:forbid,
              root_display_limit=1000, max_solutions=1000)

Find every numeral in the bounded length/radix domain that admits any positive integer external root order in the single-digit, right-associated power grammar. Root orders have no search bound and may be astronomical. root_display_limit controls formatting/materialization, never membership. Return exact RootCertificates as solutions.

For leading digit b=a^g, primitive a forces N=a^h. Write the suffix as c^T. An integer root exists iff k=h/gcd(h,g) divides c^T: every prime of k must divide c, and T must reach the largest required prime-valuation threshold. Tiny capped evaluations decide this without constructing T, c^T, or a large root. All nested powers are checked for definedness.

Return (; solutions, complete, status, candidates, method=:root_spectrum). The whole numeral domain is searched before sorting and truncation; candidates counts primitive-power numerals passing digit restrictions. Reaching max_solutions conservatively sets complete=false. Lengths must be a nonempty unit range starting at two. The zero convention, allowed digit values, and distinct-digit restriction have the same meaning as in radix_sweep.

Examples

result = root_spectrum(2:20)
x = only(filter(x -> x.number == 4294967296, result.solutions))
@assert isnothing(x.root)  # r exceeds 1000; it is retained exactly symbolically.
@assert verify_root_certificate(x)
DigitTowers.search — Function
search(config=Config(); method=:prefix, max_solutions=100)

Enumerate solutions in numerical order with an exact arithmetic backend or the original JuMP constraint model. Methods:

  • :prefix (default): exact integer logarithms locate the only possible power in each leading-digit interval; no optimizer or full power sweep.
  • :direct: enumerate primitive powers, then evaluate each candidate suffix directly with capped integer arithmetic; no optimizer.
  • :cp: build and enumerate the JuMP/HiGHS table-constraint model.
  • :nemo: use the prefix algorithm with Nemo/FLINT's exact integer logarithm; requires loading the optional Nemo package before calling search.

complete=true certifies exhaustion of the configured finite search. A solution-count limit, or a CP solver time limit, leaves it false. Every reported result is verified with integer arithmetic. The result's method identifies the backend. Config's time_limit and max_table_rows apply to CP; arithmetic methods do not build tables and are not subject to a solver timer.

DigitTowers.sweep — Method
sweep(lengths::AbstractUnitRange{Int}; roots=[2],
      allowed_digits=collect(0:9), root_digits=0,
      distinct_digits=false, zero_to_zero=:forbid, max_solutions=100)

Search several decimal lengths and root orders in one exact pass. This method supports the single-digit, right-associated power grammar. To search grouped blocks or addition, use search with a Config.

If an outer base is b=a^g and a possible answer is N=a^h, its suffix value E determines the only possible root order: r=g*E/h. The algorithm evaluates that suffix once, tests divisibility, and checks membership in roots. root_digits consumes that many leading decimal digits as the root order. Every intermediate 0^0 obeys zero_to_zero, including above a blocker.

Return (; solutions, complete, status, candidates, cap, method=:sweep). Solutions are sorted by number and root order. candidates counts distinct numbers passing the length, outer-base, consumed-root, and digit restrictions before suffix evaluation; it does not count one assignment per root. cap is the largest target-exponent bound used, with cap+1 the overflow state. Reaching max_solutions is conservatively reported as complete=false. The full range is searched before sorting and truncation, so this option limits returned results rather than the amount of work.

The length range must be nonempty and start at least at max(2, root_digits+2). As with Config, trivial one-digit answers are excluded.

Examples

result = sweep(2:100; roots=collect(1:9))
@assert result.complete
@assert only(result.solutions).number == 262144
DigitTowers.synthesize — Method
synthesize(number; roots=[2], max_block_width=3,
           max_base_width=max_block_width, allow_addition=false,
           root_digits=0, cost_weights=(concatenation=1, addition=1),
           leading_zeros_in_blocks=false, zero_to_zero=:forbid,
           max_states=1_000_000, max_exponent=1_000_000)

Find the cheapest way to turn the decimal digits of a fixed positive integer into root_r(b^suffix) == number, preserving their order. The grammar permits contiguous blocks of at most max_block_width digits and right-associated ^ (optionally also +) inside the exponent. The outer operation is always ^. The first root_digits digits, if any, specify and consume the root order. max_base_width can separately restrict the outer base; it cannot exceed max_block_width or 18. An outer base must be at least 2.

The objective is cost_weights.concatenation * (deleted digit boundaries) + cost_weights.addition * (plus signs). Weights must be nonnegative integers. One certificate is returned per feasible (root, outer-base width), sorted by cost, root, and base width. Equal-cost expressions use a deterministic tie break; alternatives with equal cost are not enumerated.

Return (; certificates, complete=true, targets, states, method=:synthesis). targets counts arithmetically possible (root, base width) pairs and states counts stored suffix-chart states; root orders share a chart for each outer-base width. Resource limits throw an error, so a returned result is complete for the specified finite grammar. State merging is exact, including powers above a zero or one and the selected 0^0 policy. This is grammar synthesis, not an unbounded claim about arbitrary expressions or arbitrary parentheses.

Examples

x = first(synthesize(262144).certificates)
@assert x.cost == 0
@assert verify(x)

y = only(synthesize(256; roots=[7], max_base_width=1).certificates)
@assert y.candidate.blocks == [2, 56]
DigitTowers.synthesize_frontier — Method
synthesize_frontier(number; roots=[2], max_block_width=3,
                    max_base_width=max_block_width, allow_addition=true,
                    root_digits=0, leading_zeros_in_blocks=false,
                    zero_to_zero=:forbid, max_states=1_000_000,
                    max_exponent=1_000_000)

Find every nondominated (concatenations, additions) cost for each feasible (root, outer-base width) in the finite grammar of synthesize. A cost is dominated when another expression uses no more of either operation and strictly less of at least one. Return one deterministic witness per cost; expressions with the same cost pair are not exhaustively enumerated.

The result contains certificates (a flat vector of SynthesisCertificate), frontiers (groups with root, base_width, and certificates fields), complete=true, targets, states, value_states, and method=:pareto. Each certificate's scalar cost is the sum of its two coordinates; both coordinates, rather than their sum, determine frontier membership. Frontiers are separate for each root/base-width pair, even when one pair's costs would dominate another pair's costs.

The chart merges equivalent capped suffix values and retains an antichain of additive cost labels per value. Root orders share a chart for each base width. states counts retained labels, while value_states counts semantic (position, value) cells. max_states guards label storage across all charts; exceeding a resource guard throws an error rather than returning a partial frontier. The returned frontier is complete for the specified grammar.

DigitTowers.tower_isdefined — Method
tower_isdefined(tokens; zero_to_zero=:forbid)

Whether a nonempty right-associated power tower of nonnegative integer tokens is defined. With 0^0 forbidden, this is exactly the condition that no two adjacent tokens are zero. A one does not hide an undefined descendant. With zero_to_zero=:one, every such tower is defined.

DigitTowers.tower_language_counts — Method
tower_language_counts(length; radix=10, leading_zero=false, zero_to_zero=:forbid)

Count defined and undefined single-digit power towers exactly, without enumerating words. Return (; defined, undefined, total) as BigInt counts. By default the first digit is nonzero, so the words represent positive numbers of exactly the requested length. leading_zero=true counts all fixed-width words instead.

The forbidden 00 language has transfer matrix [q-1 q-1; 1 0], whose states record whether the last digit is nonzero or zero. Binary matrix exponentiation takes O(log(length)) matrix products. With 0^0=1, every word is defined. This function counts validity, not fixed-point solutions.

DigitTowers.tower_mod — Method
tower_mod(word, modulus; zero_to_zero=:forbid)

Evaluate the right-associated power tower of nonnegative integers word modulo a positive integer, without constructing the tower. Return nothing if any nested 0^0 is undefined; zero_to_zero=:one defines it as one. All nested powers are checked even when an outer base is zero or one.

An Euler-totient chain and exact capped suffix values handle noncoprime bases. For example, tower_mod([2, 2, 3], 8) == 0, although naively reducing the exponent modulo phi(8) would give the incorrect answer one. Large moduli use BigInt; factoring their totient chain can be expensive. Every factorization is reconstructed and each prime factor is certified with deterministic machine-integer primality tests. A factor above typemax(Int) raises an ArgumentError; arbitrarily large powers of small primes remain supported.

DigitTowers.verify — Method

Recheck a returned assignment with integer arithmetic outside the MIP solver.

DigitTowers.verify_radix — Method
verify_radix(solution; zero_to_zero=:forbid)

Independently check the positional numeral, right-associated suffix, and exact integer power identity of a RadixSolution. No floating-point roots or logarithms are used. A digit above nine denotes that integer, not multiple decimal digits. The zero convention must match the search.

DigitTowers.verify_root_certificate — Method
verify_root_certificate(certificate)
verify(certificate::RootCertificate)

Verify the numeral, primitive-power identity, prime-valuation condition, and small-root value or strict lower bound of a RootCertificate. The algorithm never constructs an unbounded tower or an enormous root order. Every nested power must be defined according to the stored zero convention.

DigitTowers.ceil_log_power — Method
ceil_log_power(A::BigInt, a::BigInt) -> (h, number)

Return the smallest nonnegative integer h with number = a^h >= A. The positive threshold A and base 2 <= a <= typemax(Int) are exact integers. ndigits supplies an initial exponent; exact power comparisons certify and, if needed, correct both boundaries.

DigitTowers.prefix_candidates — Method
prefix_candidates(config::Config, widths; exponent_ceiling=ceil_log_power)

Generate the same necessary-condition assignments as candidate_table using exact decimal prefix windows. For base b = a^g and required prefix P, the answer must lie in [P*10^k, (P+1)*10^k). Its multiplicative width is less than two, so it contains at most one power of a >= 2. Only that power is constructed, and external root orders reuse the same window.

The exponent_ceiling hook must return (h, a^h) for the smallest h whose power reaches the supplied exact lower bound. Suffix evaluation and the all-different constraint are deliberately left to the search backend; only the universal distinct-digit pigeonhole bound is applied here.

DigitTowers.search_cp — Function

Enumerate solutions (smallest N first). complete is true only after infeasibility proves there are no remaining candidates. Hitting a solution limit or solver time limit leaves complete=false.
