Search methods and performance

Use search(config) for a fixed length and grammar, and sweep(lengths; ...) for a range of lengths in the single-digit power grammar. The original JuMP constraint model remains available with method=:cp. Every backend returns exact integer assignments and an explicit completeness flag.

Implemented methods

MethodHow it searchesBest use
:prefixLocate primitive powers in the exact leading-digit interval; check surviving suffixesDefault for a fixed Config, including grouped blocks and addition
:directGenerate primitive powers up to the length bound; evaluate candidate suffixesSimple independent arithmetic comparison
:cpJuMP finite-domain/table model, reformulated as a MIP and solved by HiGHSInspecting or extending the constraint formulation
:nemoPrefix search using Nemo/FLINT's exact integer ceiling logarithmOptional arithmetic comparison; load Nemo first
sweepEnumerate each possible number once and derive its only possible root orderMany lengths or root orders, with single-digit power towers

The arithmetic methods exploit the problem's number theory before constructing a search space. If b=a^g and N=a^h, then N^r=b^E requires r=gE/h. A sweep evaluates the suffix once per possible number and tests that quotient, rather than searching separately for every root order.

using DigitTowers

fixed = search(Config(); method=:prefix)
modelled = search(Config(); method=:cp)
range_result = sweep(2:1000; roots=collect(1:1000))
@assert range_result.complete
@assert only(range_result.solutions).number == 262144

search supports the full configured grammar. sweep supports individual decimal digits joined by right-associated powers, along with digit restrictions and consumed leading root digits. Grouped blocks and addition continue to use search.

Benchmark protocol

The reproducible suite lives in benchmark/. From the repository root:

julia --project=benchmark -e 'using Pkg; Pkg.instantiate()'
julia --project=benchmark benchmark/runbenchmarks.jl

It loads the optional Nemo backend and uses BenchmarkTools. Before timing a case, it requires complete searches, checks the exact returned assignments, and compares the solution sets across methods. Every timed evaluation calls search again, including construction of a fresh CP model. It does not reuse a solved optimizer model.

The results distinguish process import time, first-call time, and warmed end-to-end time. First-call measurements can include compilation and setup but are not clean-process cold-start measurements. Trial rows record the actual sample count, median/minimum elapsed time, allocations, and completeness. Small sample counts keep the suite short; the numbers describe these cases on the recorded machine.

Allocation counts describe Julia-managed allocations; native GMP/FLINT memory is not necessarily fully reflected in them.

For long arithmetic cases, the script estimates CP transition-table rows before building a model. A configuration exceeding max_table_rows is recorded as unsupported by that configured implementation limit. It is not a timed solver failure and provides no evidence about native CP solvers.

Raw measurements are in benchmark/results.tsv, range comparisons in benchmark/sweep_results.tsv, and environment details in benchmark/metadata.toml. The earlier research prototype and its independent oracle remain under research/ for reproducibility.

These timings record baseline commit 43a49c3. The exploration methods below were added subsequently and are not included in these benchmark tables.

Search by changing the question

The explorations use different mathematical structure rather than a larger enumeration budget:

MethodReductionWhat it certifies
root_spectrumPrime valuations turn divisibility by an enormous suffix into a tiny thresholdEvery root order, including ones too large to materialize, over bounded numeral lengths
synthesizeMerge suffix parses with the same capped value, retaining the cheapestMinimum expression cost in its finite partition/operator grammar
synthesize_frontierRetain a Pareto antichain instead of scalarizing cost labelsEvery nondominated join/addition tradeoff in that grammar
anagram_towersMerge permutations with the same remaining digit counts and capped suffix valueMinimum changed positions for every feasible root/base pair
tower_modA totient chain with exact small/large flagsExact residues, including noncoprime bases
modular_dynamicsExhaust the finite map once, then walk its functional graphEvery cycle and its full basin in the configured domain
modular_nearpointsUse low-digit congruences as admissible distance boundsExact closest points and tie counts, skipping many full evaluations
modular_orbitBrent cycle detection keeps only a constant number of orbit statesLeast preperiod and period for one start, or an explicit evaluation limit
tower_language_countsBinary powers of a two-state transfer matrixExact defined/undefined word counts in logarithmically many matrix products

For example, the 1000-digit decimal root spectrum starts from only 1,702 primitive-power numerals. The forbidden-00 language rejects 1,509 immediately; 193 are defined, and the valuation test leaves three solutions. This removes the need to search over root orders at all. The synthesis census likewise reuses 57,063 value states instead of enumerating every partition of every candidate. These counts describe the saved experiments; they are not timing comparisons with the earlier fixed-grammar benchmarks.

Primes exposes both factorization and a lazy iterator of factor/multiplicity pairs. Nemo documents exact floor and ceiling integer logarithms (flog/clog), as well as checked integer roots. These are directly useful for the primitive-power reduction. Primes API, Nemo integer API

ConstraintSolver.jl propagates bounded discrete domains before branching and backtracking. We have not benchmarked it against this package. A future native CP implementation should compare a suitable propagator or representation, rather than assume that changing the solver removes the cost of large explicit tables. The measurements here do not establish HiGHS as the best CP solver. ConstraintSolver explanation

Within JuliaConstraints, ConstraintProgrammingExtensions.jl supplies MOI representations for CP constraints; it is not itself a search solver. CBLS/LocalSearchSolvers provides heuristic local-search machinery. A heuristic that does not find an answer cannot, by itself, certify that no answer exists. ConstraintProgrammingExtensions, JuliaConstraints ecosystem, CBLS tutorial

Why certified intervals remain optional

Arblib supplies arbitrary-precision balls with rigorous error bounds, while IntervalArithmetic.jl supplies validated interval calculations. Either could support a leading-digit screen for extremely large powers. The current prefix implementation uses exact integer comparisons, so it already avoids rounding uncertainty. Additional numerical dependencies should be justified by profiling. Arblib types, IntervalArithmetic documentation

Any future interval screen must refine ambiguous bounds until the endpoint floors agree. A ball containing a unique integer does not alone certify a floor: [122.9,123.1] contains one integer but permits two floor values. Surviving candidates still require exact suffix validation, including every nested 0^0 under the default policy.
